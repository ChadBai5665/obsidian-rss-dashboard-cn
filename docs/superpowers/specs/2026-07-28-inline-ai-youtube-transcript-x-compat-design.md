# 内联 AI、YouTube 字幕与 X 资料兼容设计

日期：2026-07-28  
状态：已确认设计，实施计划已完成

## 1. 背景与问题

当前版本有三个相互关联的使用问题：

1. X 账号输入本身正确，TikHub 请求也能到达服务端，但本地资料投影器对实际返回结构过于严格，合法账号仍可能得到“账号资料格式暂不支持”。
2. 单条内容的 AI 操作先打开一个大型“发送前确认”弹窗。弹窗没有与信息台统一的专属布局，信息密度和空间比例失衡；同时现有 OpenAI 兼容请求明确使用非流式模式，用户需要确认后等待完整响应。
3. YouTube 当前只采集 Feed 标题和简介。内嵌播放器运行在 Obsidian/Electron 的独立会话中，不共享 Chrome 登录状态；字幕/逐字稿尚未实现。

本轮把三处体验收敛为一个原则：订阅和阅读操作应在当前内容上下文中直接完成；需要模型或外部服务时，界面只展示必要状态，结果必须有可恢复的本地 Markdown 真值。

## 2. 目标

- X 账号只要求用户输入 `@handle`、纯 handle 或账号主页地址；合法资料结构能够显示头像、名称和账号供确认。
- 文章阅读区提供“获取全文/字幕、生成摘要、翻译、核心观点、深度分析”等明确按钮。
- AI 操作不再显示发送前确认弹窗；点击具体操作就是对“当前单条内容 + 当前默认连接”的一次明确授权。
- AI 文本在当前阅读区内直接流式显示，不请求或展示模型思维链。
- 已生成结果优先从本地 Markdown 恢复；收起、切换页面或重新打开不会自动重新调用模型。
- 重新生成必须由用户明确点击，并创建新版本，不覆盖旧结果。
- YouTube 的“获取全文”表示获取公开字幕/逐字稿；没有字幕时明确失败，不用标题和简介冒充全文。
- YouTube 主播放动作交给操作系统默认浏览器（当前为 Chrome），保留次要的内嵌预览入口。
- 更新继续保护既有 API Key、订阅配置、采集历史、全文缓存和用户 Markdown。

## 3. 非目标

- 不读取、导入或复制 Chrome Cookie。
- 不在 Obsidian 中实现 Google/YouTube 登录。
- 不调用付费第三方字幕服务，也不下载视频或音频进行 Whisper/ASR 语音识别。
- 不自动摘要、自动翻译、自动评分或后台生成 Top 10。
- 不自动切换备用模型，不自动重试产生费用的 AI 或 TikHub 请求。
- 不保存或展示模型隐藏思维链；“深度分析”只是更完整的分析任务，不等于开启推理模式。
- 不覆盖已有 AI 结果或用户保存的正式笔记。

## 4. 交互设计

### 4.1 单一阅读上下文

阅读器的文章操作区提供紧凑按钮：

- 获取全文；YouTube 显示“获取字幕”。
- 生成摘要。
- 翻译为简体中文。
- 提取核心观点。
- 深度分析。

在文章列表或右键菜单中选择上述操作时，先打开对应文章的阅读器，再在同一位置展开结果。列表卡片本身不承载长文本，避免再次产生拥挤布局。

### 4.2 内联结果面板

结果面板位于文章标题/操作区之后、原文内容之前，宽度跟随阅读正文，不使用全屏或大型 Modal。面板包含：

- 操作名称、生成时间、内容依据、连接名称和实际模型。
- 状态行：准备内容、获取字幕、正在生成、正在保存、完成或明确错误。
- 流式正文区域。
- 收起/展开。
- 生成中显示“停止生成”。
- 完成后显示“重新生成”“打开 Markdown”“保存或插入知识库”“历史版本”。
- 多个 AI 连接存在时提供一个紧凑连接下拉框；默认直接使用已配置的默认连接，不再弹出确认页。

关闭或收起只改变显示状态，不删除结果，也不中止正在运行的任务。只有“停止生成”才发送中止信号。

### 4.3 防重复调用

运行任务按 `itemId + operation` 建立内存协调键：

- 同一任务生成中再次点击，只重新展开并接回现有流，不创建第二个请求。
- 已有成功结果时再次点击，直接读取并显示最近版本，不调用模型。
- 只有“重新生成”创建新请求。
- 完全退出 Obsidian 或停用插件时中止未完成请求；不保存空白或残缺分析 Markdown。

### 4.4 错误状态

错误在内联面板中显示，不打开新的错误弹窗：

- 未配置连接或 API Key：显示“配置 AI 连接”按钮。
- Key 失效、余额不足、限流、超时、网络失败和服务端拒绝：显示对应中文原因和“重试”入口。
- 字幕不存在：显示“该视频没有可用字幕”，保留“在浏览器中播放”。
- 字幕结构变化或暂时不可取：与“没有字幕”分开显示，避免误导。
- 失败不创建 AI 分析文件，也不更改原始采集数据和已保存笔记。

## 5. 本地持久化与版本历史

### 5.1 AI 结果

沿用现有不可变分析文件结构：

```text
{dataFolder}/analysis/{itemId}/{UTC时间}-{operation}.md
```

默认 `dataFolder` 为 `.rss-dashboard-data`。每次成功生成创建一个新文件；文件继续记录来源条目、操作、生成时间、连接、服务商、实际模型、内容依据、输入字符数和截断状态。API Key、请求头和服务商原始响应不写入文件。

分析仓库增加只读查询能力：列出某条内容的分析文件，安全解析插件拥有的 frontmatter，并按生成时间返回指定操作的最近结果和历史版本。查询直接以文件系统为真值，不额外维护易漂移的索引文件。

“打开 Markdown”打开当前版本；“保存或插入知识库”继续使用已有的所有权校验，不能静默覆盖用户文字。用户修改过的分析文件不再被当作可安全插入的插件原件，但仍保留在本地。

### 5.2 文章全文与 YouTube 字幕

内容缓存继续使用：

```text
{dataFolder}/content/{itemId}.md
```

普通文章保持 `full-text`。YouTube 字幕新增明确的 `youtube-transcript` 内容依据，文件记录视频 ID、字幕语言、人工/自动字幕类型和获取时间。正文保存规范化逐字稿；界面同时显示字幕语言和类型。AI 输入使用去除重复时间标记后的正文，并继续遵守连接的最大输入字符限制。

再次点击“获取字幕”优先展示缓存；“重新获取”才重新访问 YouTube，并以原子替换方式更新该条字幕缓存。重新获取字幕不会自动重新生成旧摘要，旧结果继续显示其原内容依据；用户可明确点击重新生成。

## 6. AI 流式架构

### 6.1 服务接口

文本生成提供器增加流式接口，以受控的文本增量事件输出最终答案。业务层负责：

- 选择当前单条内容并构建提示词。
- 将增量转交内联面板。
- 累计并限制最大输出字符数。
- 只在完整成功后生成最终 `AiAnalysisResult` 并原子保存 Markdown。

UI 不直接接触 API Key、认证头或服务商原始事件。

### 6.2 协议

- OpenAI Chat Completions 兼容连接使用 `stream: true`，只读取 `choices[].delta.content` 等最终文本字段。
- Anthropic Messages 兼容连接读取文本内容块增量。
- 不发送 `reasoning_effort`、`thinking` 或要求输出思维过程的参数；提供商返回的 reasoning/thinking 字段不进入界面或 Markdown。
- 官方服务商预设和自定义中转站共用边界解析器，但不得为兼容性自动发起第二次请求。
- 如果服务端忽略流式参数并在同一次响应中返回普通 JSON，允许一次性显示最终文本，并提示“服务端未返回流式内容”；不能为了“尝试流式”重复计费。

### 6.3 桌面传输

插件保持桌面端限定。流式传输在桌面运行时读取响应流，支持超时、中止、最大响应限制和安全的 HTTP(S) 地址校验。重定向必须重新校验目标，不把认证头转发到不同源站。日志和错误不得包含 API Key、认证头、完整请求正文或模型原始响应。

## 7. YouTube 字幕与播放

### 7.1 字幕

“获取字幕”只访问当前公开视频的 YouTube 页面和公开字幕轨道：

- 首选插件内置的 InnerTube 字幕发现与下载逻辑；该逻辑以本机现有 `baoyu-youtube-transcript` 的已验证实现为参考，但发布包不依赖 Codex skill 目录。
- InnerTube 被 YouTube 拦截或返回不可解析结构时，如本机检测到可执行的 `yt-dlp`，允许对同一视频调用一次本地字幕回退；不下载视频或音频。
- `yt-dlp` 是可选桌面增强，不是公开仓库用户的必需依赖。未安装时跳过本地回退并返回明确状态。
- 调用本地程序时只传经过验证的视频 ID、字幕语言和固定参数，不拼接或执行用户提供的命令文本。
- 优先人工原语言字幕，其次自动生成的原语言字幕。
- 多个同优先级轨道存在时显示紧凑语言选择，不打开大型弹窗。
- 不携带 Chrome Cookie，不承诺访问会员、私密、年龄限制或需登录内容。
- 没有公开字幕轨道时立即停止，不用视频简介伪造逐字稿。
- YouTube 页面或字幕格式发生变化时返回单独的“字幕暂时无法解析”错误。
- 如果人工字幕、自动字幕、InnerTube 和本地 `yt-dlp` 均无可用轨道，视为“确实没有字幕”；本轮不自动转向 Whisper/ASR。

### 7.2 播放

- 主播放按钮调用系统默认外部浏览器；当前默认浏览器为 Chrome 时会复用 Chrome 已有登录状态。
- 次要按钮“内嵌预览”继续使用隐私增强的 YouTube iframe。
- 内嵌受限或播放失败时持续显示“在浏览器中播放”，不提示用户在 Obsidian 中登录。
- 插件不访问任何浏览器 Cookie 存储。

## 8. X 账号资料兼容

### 8.1 解析规则

TikHub 资料解析继续采用边界遍历和字段白名单，只投影：

- `restId`。
- handle。
- 显示名称。
- 可选头像。
- 可选简介。
- 可选认证状态。

兼容规则调整为：

- 可选容器或可选值缺失、空字符串或 `null` 时按“未提供”处理。
- legacy 与 current/core 身份字段可同时出现；归一化后的 handle 和身份一致时合并，冲突时拒绝。
- 同一账号在不同包装层重复出现时按稳定身份去重；多个不同账号候选仍拒绝。
- 必需的 rest ID、handle 或显示名称缺失/非法时拒绝。
- 不保存 TikHub 完整响应、缓存地址、请求 ID 或其他未白名单字段。

### 8.2 可诊断性与费用

若仍遇到不支持结构，只生成不含字段值的本地结构摘要：容器类型、允许字段是否存在、候选数量和冲突类型。该摘要不含账号正文、API Key、URL 参数或服务商原始数据，用于下一次修复时定位边界。

每次“识别并检验”最多产生一次 TikHub 请求；编辑输入会清除旧确认状态，但不会自动请求。插件更新、重启和重新打开弹窗也不会自动计费。

## 9. 数据迁移与更新安全

- 不修改现有 AI 连接 ID、默认连接、API Key 外部存储位置或 TikHub 连接设置。
- 现有 schemaVersion 1 AI Markdown 可直接进入历史列表，不要求重写。
- 新的字幕内容依据通过向后兼容的联合类型加入；现有 `full-text` 文件继续可读。
- 安装继续在 Obsidian 完全退出时执行，先备份程序目录并逐项校验 `data.json`、外部密钥文件、采集历史目录及 Markdown 文件计数/哈希。
- 安装器只替换 `main.js`、`manifest.json` 和 `styles.css`，不清理旧分析版本、全文缓存或订阅历史。

## 10. 验收标准

1. `@naval` 或等价公开账号能够显示 TikHub 返回的账号名称供确认；无冲突的 legacy/current 双结构和空可选字段均通过测试。
2. AI 操作不再创建发送前确认 Modal。
3. 从列表点击 AI 操作会打开对应阅读器，并在文章内联面板中执行。
4. 支持流式的官方连接能逐段显示最终文本；无 reasoning/thinking 内容泄漏。
5. 同一条内容同一操作生成中重复点击不会创建第二次请求。
6. 收起再展开继续显示当前任务；完成后重新打开直接读取最近 Markdown，不调用模型。
7. “重新生成”创建新文件，旧版本仍可从历史中打开。
8. 无 Key、Key 失效、余额不足、限流、超时和网络错误均显示对应内联状态，不创建空文件。
9. YouTube “获取字幕”成功时保存并显示真实公开字幕；无字幕时明确失败且不调用 AI。
10. InnerTube 失败时，本机存在 `yt-dlp` 才执行一次固定参数的字幕回退；缺少本地工具不会阻塞其他功能，也不会触发安装。
11. 主播放按钮在外部浏览器打开视频；次要内嵌预览仍可用于允许嵌入的公开视频。
12. 更新前后的 API Key、配置、订阅、历史、全文、AI 分析和用户 Markdown 均保持。
13. 完整单元测试、i18n 审计、公开仓库扫描、类型检查、构建、发布包校验和 GitHub CI 全部通过。

## 11. 发布边界

本设计纳入现有来源订阅 PR 的后续提交，但在以下真实验收完成前不合并：

- 一个公开 X 账号成功识别，并验证取消“全部历史”确认不会保存来源或产生帖子请求。
- 一个带公开字幕的 YouTube 视频完成字幕获取、缓存恢复、AI 流式生成、收起/展开和重新生成版本验证。
- 一个不能内嵌播放的视频能够通过主按钮在外部浏览器打开。
