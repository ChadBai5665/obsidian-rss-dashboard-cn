# 信息源订阅与首次导入体验设计

- 日期：2026-07-27
- 状态：对话设计已确认，等待进入实施计划
- 适用插件：RSS Dashboard CN
- 范围：RSS/网站、YouTube、X 账号的添加、验证、首次导入和统一管理

## 1. 背景

现有实现已经具备 RSS 预览、YouTube 频道转官方 RSS、TikHub X 账号采集等底层能力，但添加流程仍以开发配置为中心：

- X 账号只能从设置深处添加，并要求用户填写显示名称、文件夹和主题等非必要字段。
- RSS、YouTube 和 X 没有统一、清晰的外部入口。
- RSS/YouTube 的“加载”结果分散在标题、最新条目和状态字段中，缺少明确的身份确认卡片。
- 保存操作不依赖验证成功；失败后还可能残留上一次成功识别的名称和文件夹。
- YouTube `@handle` URL 会先命中 Mastodon 路径规则，导致成功解析后仍显示 Mastodon 转换提示并分配错误文件夹。
- 普通网站地址没有完成设计规格中约定的 RSS/Atom 自动发现。
- 首次订阅没有“从何时开始导入”的用户选择。

本次设计把“添加订阅”改造成面向普通用户的短流程，同时保持 API、密钥、额度和默认目录等基础设施配置在设置页面。

## 2. 设计目标

1. 用户从 Dashboard 主界面即可添加和管理 RSS/网站、YouTube、X 账号。
2. 添加前必须先识别来源并明确展示“识别到了谁/哪个站点、是否连接成功”。
3. 用户只填写来源的唯一标识；显示名称、规范地址和默认文件夹由系统识别或自动分配。
4. 任何失败或输入变更都立即使旧验证结果失效，未验证内容不能保存。
5. 首次订阅支持选择历史导入范围，默认最近 7 天。
6. 后续刷新只合并新增内容并去重，不重复制造历史条目。
7. TikHub 的分页、回复采集和历史导入必须受请求额度与费用提示保护。
8. 更新功能不得覆盖现有 API Key、设置、采集历史或已保存 Markdown。

## 3. 非目标

- 不增加自动摘要、自动翻译、Top 10 或价值评分。
- 不在 Obsidian 关闭时运行后台服务。
- 不承诺突破来源平台本身提供的历史范围。
- 不将 TikHub、AI 或存储配置迁移到 Dashboard 的日常订阅流程。
- 不删除用户已经保存为 Markdown 的内容。

## 4. 信息架构

### 4.1 主界面入口

Dashboard 顶部继续保留一个明显的“添加订阅”按钮。点击后打开来源选择页，而不是直接展示混合表单。

来源选择页包含三个等权重大卡片：

1. **RSS / 网站**：粘贴网站首页、RSS、Atom 或 JSON Feed 地址。
2. **YouTube**：粘贴频道主页、`@频道名` 或频道 ID。
3. **X 账号**：输入账号、`@账号` 或 X/Twitter 个人主页地址。

卡片使用来源名称、图标、一句话说明和输入示例。点击卡片后在同一个窗口中切换到对应流程，左上角提供“返回选择来源”。不得继续叠加第二层 Modal。

Dashboard 同时保留“管理订阅源”入口。X 主题发现继续作为 Dashboard 的独立页面，不与固定账号订阅混在一起。

### 4.2 设置页面边界

以下内容继续留在设置页面：

- TikHub 大陆版、国际版或自定义接口地址。
- TikHub API Key、连接测试、超时、单次和每日请求上限。
- AI 服务商、API Key、模型和兼容接口设置。
- RSS、YouTube、X 等来源的默认文件夹和默认标签。
- 全局刷新、保留时长和条目上限。

设置页面不再作为添加日常订阅的主要入口，但可提供一个跳转到 Dashboard“添加订阅”的辅助链接。

## 5. 通用添加流程

每种来源使用相同的五步状态机：

```text
选择来源 → 输入唯一标识 → 检测中 → 确认识别结果 → 选择首次导入范围 → 订阅成功
                               ↘ 检测失败 → 修改或重试
```

### 5.1 初始状态

- 只展示一个主要输入框和“检测”按钮。
- “确认订阅”按钮不可用或不显示。
- 文件夹、标签、过滤规则收进“高级设置”，默认不要求填写。

### 5.2 检测中

- 展示明确的进行中状态，例如“正在检测 YouTube 频道……”。
- 防止重复点击，但允许用户取消。
- 超时后进入可恢复的失败状态，不无限等待。

### 5.3 检测成功

成功后显示只读确认卡片，明确回答：

- 识别到的来源类型。
- 来源名称或账号身份。
- 规范化后的来源地址或账号。
- 最近一条内容及其时间。
- 当前是否能够正常获取内容。

内部 RSS 地址、游标等实现细节默认隐藏，可在“连接详情”中查看。

### 5.4 检测失败

- 给出用户可理解的具体原因：地址格式错误、没有发现订阅源、频道不存在、TikHub 未配置、密钥失效、额度不足、网络超时等。
- 提供“重新检测”或“前往设置”动作。
- 不要求普通用户打开开发者控制台。
- 清除旧标题、旧文件夹、旧类型和旧成功状态。
- “确认订阅”保持不可用。

### 5.5 输入失效规则

输入内容只要发生改变，上一轮验证结果立即失效。用户必须重新检测，不能把 A 来源的识别结果和 B 来源的地址组合保存。

## 6. 各来源检测设计

### 6.1 RSS / 网站

接受：

- RSS、Atom、JSON Feed 的直接地址。
- 普通网站首页或栏目页地址。

检测顺序：

1. 将输入规范化为安全的 HTTP(S) URL。
2. 直接请求并判断是否为可解析的 RSS、Atom 或 JSON Feed。
3. 若为 HTML，解析页面声明的 `alternate` feed 链接。
4. 必要时尝试有限、明确的常见 feed 路径；不得变成通用网页爬虫。
5. 验证候选订阅源至少能够解析元数据；无条目时显示警告而不是伪装成正常。

若同一网站发现多个订阅源，展示名称、类型和地址列表，由用户选择一个。不得静默选择第一个。

成功卡片展示：网站/订阅源名称、类型、域名、最新文章标题和时间。普通网站解析成 feed 后保留原网站地址和规范 feed 地址的关联。

### 6.2 YouTube

接受：

- `https://www.youtube.com/@handle`
- `@handle`
- `UC...` 频道 ID
- `youtube.com/channel/...`
- 仍受支持的旧式用户或自定义频道 URL

识别顺序必须先判断明确的平台域名，再判断通用的路径形状。YouTube 的 `/@handle` 不得再被 Mastodon 规则抢先识别。

成功卡片展示：YouTube 标识、频道名称、规范频道地址、最新视频标题和时间。内部 `feeds/videos.xml` 地址默认隐藏。

视频页、播放列表或搜索页不应被误认为频道；如暂不支持从视频反查频道，应给出明确提示并引导用户粘贴频道主页。

### 6.3 X 账号

接受：

- `OpenAI`
- `@OpenAI`
- `https://x.com/OpenAI`
- `https://twitter.com/OpenAI`

统一规范化为 X `screen_name`，再调用 TikHub 用户资料接口进行身份确认。

成功卡片展示：头像、显示名称、`@handle`、个人简介（可用时）和认证信息（可用时）。确认身份后才展示来源选项：

- 包含回复：默认关闭；开启时明确提示会增加 TikHub 请求。
- 包含转发：默认关闭；只影响过滤，不伪装成额外身份验证。

主要流程不再要求手填显示名称、文件夹或主题标签。账号更名或修改 handle 时必须重新检测。

## 7. 首次导入范围

检测成功后展示“首次导入范围”，统一默认最近 7 天。

可选项：

- 仅从现在开始
- 最近 3 天
- 最近 7 天（默认）
- 最近 14 天
- 最近 30 天
- 最近 90 天
- 自定义天数或起始日期
- 全部可获取历史

该设置只控制首次订阅时导入的历史范围。后续刷新依据稳定条目 ID 和最后成功状态进行增量合并与去重。

### 7.1 来源能力边界

- **RSS / 网站**：“全部”表示当前 feed 响应中仍然存在的全部条目，不承诺网站建站以来的全部文章。
- **YouTube**：“全部”表示 YouTube 官方频道 feed 当前可返回的全部视频，不承诺整个频道历史。
- **X**：通过 TikHub 返回的分页游标逐页向前读取，直到达到起始日期、没有下一页、用户停止或触发请求上限。

界面必须在选择结果附近解释这些边界，避免把“用户选择的时间范围”误解为“平台保证能返回的完整历史”。

### 7.2 X 全量历史保护

X 选择“全部可获取历史”时：

- 开始前进行二次确认并说明每页可能产生一次计费请求。
- 展示已经请求的页数、获得条数和当前最早日期。
- 受单次和每日 TikHub 请求上限保护。
- 允许用户随时停止，已成功获取的内容保留。
- 保存分页进度；当天额度耗尽后，可在后续刷新时继续，不从头开始。
- 包含回复时单独计算回复时间线的请求，不能低估费用。

## 8. 后续刷新与去重

- 新订阅完成首次导入后记录首次成功时间、最早已导入时间和来源进度。
- RSS/YouTube 每次刷新仍可收到来源窗口中的重复条目，按稳定 URL、GUID 或视频 ID 去重。
- X 按推文 ID 去重；需要追赶断档时使用最后已知 ID、时间和游标状态控制分页。
- 每天打开 Obsidian 自动刷新机制保持不变。
- 一个来源失败不阻塞其他来源。
- 用户手动刷新可以重试失败来源，但仍遵守 TikHub 上限。

## 9. 统一订阅管理

“管理订阅源”统一列出 RSS/网站、YouTube 和 X 账号，并提供来源类型筛选。

每个来源展示：

- 名称、类型和规范标识。
- 正常、失败、暂停或首次导入未完成状态。
- 最近成功刷新时间。
- 最近一次错误摘要。
- 初次导入范围和进度（仍在执行时）。
- 手动刷新、暂停、编辑、删除。

同一个规范 feed URL、YouTube 频道 ID 或 X handle 不允许重复订阅。修改唯一标识时必须重新验证；修改标签、文件夹、回复/转发开关等不改变身份的设置时不要求重复验证。

## 10. 删除与数据安全

### 10.1 删除默认行为

删除订阅默认只停止未来采集并移除来源配置：

- 已采集历史保留。
- 已保存 Markdown 保留。
- 手动 AI 结果保留。

若用户同时希望删除来源的本地采集缓存，必须额外勾选，并再次确认。已保存 Markdown 永远不随订阅删除自动移除。

### 10.2 更新与迁移

- 程序更新只替换构建产物和 manifest，不删除数据目录、设置文件或外部密钥文件。
- 配置 schema 采用向前兼容的增量迁移；新增字段提供安全默认值。
- 安装本地新版本前备份现有设置、非敏感来源配置和数据索引；密钥按现有外部秘密存储机制保留，不复制进仓库或日志。
- 迁移失败时保持旧数据不变，并给出可恢复提示。

## 11. 建议的内部边界

实现时建议拆为以下职责，避免继续把所有来源逻辑塞入一个 Modal：

1. `AddSourceHub`：三卡片入口和同窗步骤切换。
2. `SourceIdentifierNormalizer`：平台优先的输入识别与规范化。
3. `RssWebsiteDiscovery`：直接 feed 验证和 HTML feed 自动发现。
4. `YouTubeChannelResolver`：频道身份与官方 feed 解析。
5. `XProfileResolver`：TikHub 资料查询与身份确认。
6. `SourceVerificationState`：空闲、检测中、成功、警告、失败、失效状态。
7. `InitialImportPolicy`：首次导入范围、来源能力边界和 X 分页预算。
8. `SubscriptionManager`：统一列表、编辑、暂停和安全删除。

底层适配器继续输出现有统一 Feed/CollectedItem 结构；本次不引入第二套采集存储。

## 12. 错误与恢复

至少区分以下错误：

- 输入为空或格式不合法。
- 来源不受支持。
- 网站可访问但没有发现 feed。
- feed 可访问但不可解析。
- feed 正常但当前没有条目。
- YouTube 频道无法解析。
- X 账号不存在或已受限。
- TikHub 未启用、未配置 Key、Key 无效、余额不足、被限流、服务异常或网络超时。
- 首次导入因额度用完而暂停。

错误消息不得包含 API Key、完整响应体或要求用户查看控制台。必要的技术诊断只写入脱敏日志。

## 13. 验收标准

### 13.1 入口与布局

- Dashboard 点击一次“添加订阅”可看到三个大卡片。
- 三种流程在同一 Modal 中切换，并能返回来源选择页。
- 常规桌面宽度和窄窗口下均不越界、不横向滚动。

### 13.2 验证安全

- 正确 RSS 地址能显示来源名称、最新条目和连接成功状态。
- 普通网站能自动发现一个或多个 feed；多个候选必须由用户选择。
- 没有 feed 的网站得到明确失败提示。
- YouTube `@handle`、频道主页和频道 ID 能正确识别为 YouTube，不得显示 Mastodon。
- 正确 X 账号显示身份确认卡；错误账号不能保存。
- 修改任何唯一标识后，旧确认卡和成功状态立即失效。
- 未验证、验证失败或验证过期时不能确认订阅。

### 13.3 首次导入

- 默认选中最近 7 天。
- 用户可选择预设、自定义起始日期和全部可获取历史。
- RSS/YouTube 明确展示平台可用历史的边界。
- X 分页受到单次与每日上限保护，并能保存断点继续。
- 后续刷新不重复生成首次导入的条目。

### 13.4 管理与保留

- 三种来源可在外部统一管理。
- 重复来源被识别并阻止添加。
- 删除来源默认保留历史和 Markdown。
- 升级后 API Key、用户配置、采集历史和已保存 Markdown 保持可用。

### 13.5 回归测试

- RSS、YouTube、Podcast、Mastodon 和 Nitter 现有解析路径不因识别优先级调整而回归。
- 每日打开 Obsidian 自动刷新、手动刷新、失败重试和配额记账继续工作。
- 设置页的 TikHub 与 AI 连接测试继续工作。

## 14. 已确认的产品决策

- 采用单一“添加订阅”入口，进入后显示三个大卡片（方案 B）。
- 卡片后续流程在同一窗口内完成，不叠加 Modal。
- 多个 RSS 候选由用户选择，不自动取第一个。
- 删除订阅默认保留已经采集的历史内容和 Markdown。
- 首次导入默认最近 7 天，可手动调整或选择全部可获取历史。
- X 全量历史必须显示费用风险、二次确认并受额度上限保护。
