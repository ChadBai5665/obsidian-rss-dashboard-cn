# RSS Dashboard CN 中文故障排查

## 插件没有出现在列表中

确认目录和文件是：

```text
{vault-root}/.obsidian/plugins/rss-dashboard-cn/
  main.js
  manifest.json
  styles.css
```

- 文件夹名不能是 `rss-dashboard` 或压缩包名称。
- 三个文件要直接放在 `rss-dashboard-cn` 下。
- 允许 Obsidian 第三方插件后，重新加载或完全重启应用。
- 确认你复制文件的知识库就是当前打开的知识库。
- 更新时同时替换三个文件，避免版本混用。

## 打开 Obsidian 后没有自动刷新

- 默认模式只在 Obsidian 打开且布局就绪后运行，不是系统后台任务。
- 同一本机日期内已经成功刷新的来源不会再次自动刷新。
- 默认有 5 秒启动延迟，可在设置中调整。
- 被排除、已停用或没有任何订阅的来源不会刷新。
- 需要立即更新时，使用“刷新全部来源”“刷新失败来源”或单一来源刷新。

若来源显示失败，先手动刷新一次并查看结构化错误提示。

## RSS、网站或播客刷新失败

1. 在浏览器中确认来源地址仍可访问。
2. 检查来源是否从 HTTP 跳转到 HTTPS，或要求登录、Cookie、地区权限。
3. 核对“设置 → 常规 → 代理”。默认已启用 CORS 代理并使用“自动轮换”；Feed 会先尝试直接请求，失败后可能轮换第三方公共代理。
4. 网站没有标准 Feed 时，自动发现可能失败，可以改用网站公开提供的 RSS/Atom 地址。
5. 网页正文提取失败不等于 Feed 采集失败；仍可保存 Feed 中已有的标题和简介。

代理请求会携带经过编码的完整目标 URL，代理运营方可以还原并看到该地址。预设代理不构成隐私或可用性背书，也可能限流、记录请求或下线。你可以关闭代理或配置自己信任的地址，但关闭 CORS 代理可能降低部分跨域订阅源和全文抓取的成功率。

## 只浏览页面却出现了网络请求

信息采集和界面渲染是不同的联网路径。打开信息台、文章列表、侧边栏或发现页时，界面可能自动加载远程封面、正文图片、播客图片以及 Google favicon；这些请求可能暴露 IP 地址、来源域名或目标域名。关闭自动刷新不会阻止浏览器加载所有远程图片。

只有点击“内嵌预览”后才会请求 `youtube-nocookie.com`；仅打开文章或使用系统默认浏览器播放不会创建这个内嵌请求。它是隐私增强嵌入域，但仍属于第三方请求。

保存到本地 Markdown 只保证文本文件在知识库中；其中的远程图片或媒体 URL 不会自动变成本地附件。再次打开并渲染这份本地 Markdown 时，Obsidian 仍可能请求远程资源。

## YouTube 字幕或播放不可用

日常刷新只采集频道/视频 Feed 和元数据。打开单条视频后，需要明确点击获取字幕；内置路径只尝试 YouTube 当前公开提供的公开人工字幕或自动生成字幕。标题和简介不会被表示为字幕，也不会补进字幕正文。

没有公开字幕轨道时，界面会显示“无字幕”，这和暂时无法解析是两个不同状态。内置路径明确确认没有公开字幕后，即使可选工具或字幕提供方不可用、无轨或临时失败，最终也保持“无字幕”。如果回退已取得有效字幕但本地保存失败，界面会显示暂时不可用，不会误报“无字幕”。

- 显示“无字幕”：该视频没有可用的公开字幕轨道；本版本不伪造字幕，也不包含语音识别。
- 显示“需要登录”：公开字幕路径本身要求登录，插件不会读取浏览器 Cookie 或建立 YouTube 登录。
- 显示“暂时不可用”：YouTube 的公开响应结构、限流或网络状态可能变化。稍后明确点击“重新获取字幕”，不要连续重试。
- 已显示缓存：再次打开文章只读取本地缓存，不联网。只有“重新获取字幕”会请求并替换缓存。

插件可以使用本机已有的 `yt-dlp` 作为可选回退，但不要求安装，也不会自动安装或更新。若你已经在 macOS 自行安装，可以只检查：

```bash
yt-dlp --version
```

看不到版本表示本地回退不可用，但内置公开字幕路径仍会优先尝试。不要添加 Cookie、浏览器认证或下载参数；本版本不下载视频或音频，也不使用 Whisper、ASR、FFmpeg、Python、Bun 或字幕 SaaS。安装 `yt-dlp` 不能为原本没有公开字幕的视频生成字幕。

主播放按钮会用操作系统的系统默认浏览器打开 YouTube；“内嵌预览”才在 Obsidian 中加载播放器。内嵌预览与系统默认浏览器的登录状态不相通，所以浏览器已登录不代表内嵌预览已登录。地区、年龄、账号、网络策略或 YouTube 自身限制仍可能影响播放。

## TikHub/X 无法刷新

依次检查：

1. TikHub 功能已启用。
2. 已保存有效 API 密钥，并且连接测试通过。
3. 基础接口地址仍符合当前 TikHub 文档。
4. 单次请求上限足够完成这轮计划。
5. 当日请求上限尚未达到。
6. TikHub 账户有可用额度，接口未限流或下线。

密钥缺失、失效、预算不足或请求账本异常时，插件会阻止 X 请求；普通 RSS、网站、播客和 YouTube 不受影响。

主题发现中的“平台 `Top`”只是搜索类别，不是质量分数。如果结果不相关，应调整包含关键词、排除关键词、观察窗口和重点账号，而不是把 `Top` 当成推荐。

## 运行记录显示不完整、损坏或健康警告

从“RSS 信息台 → 运行记录”查看最近 7 天的操作；需要更长时间时切换到最近 30 天。设置页的“导入与导出 → 诊断信息”也提供查看、脱敏导出和清空入口。

- “部分日期的记录不完整”：常见原因是应用退出时最后一行尚未完整写入。更早的合法记录仍会显示。
- “部分记录已损坏”：某个日期文件存在无法验证的中间行；插件会跳过损坏行并保留其余合法事件，不会把未知内容猜成正常记录。
- “最近一次记录写入失败，本次记录可能不完整”：原来的字幕、AI、刷新或订阅操作仍按自身结果结束，但这次时间线可能缺少阶段。
- “记录维护未完成”：保留或容量清理没有完成；已有可用记录仍可查看，稍后重开信息台或 Obsidian 再检查。
- “可能中断”：一项操作只有开始/进度事件，在该类别的保守时间窗后仍没有终态。这是读取时的提示，不等于业务已被判定为失败。

先重新打开运行记录并检查健康提示，再生成脱敏预览用于报告问题。不要直接修补、拼接或删除 JSONL 行；手工修改可能让原本可读取的日期变成损坏记录。日志位于当前数据根下的 `state/operation-journal/YYYY-MM-DD.jsonl`，这个相对路径只供高级排障定位，普通用户不需要查看或手工编辑。

“清空记录”会再次确认，并且只清除运行记录。它不会删除配置、密钥、订阅、字幕、采集内容与历史、AI 分析或 Markdown。若这些业务数据也需要清理，请按 [隐私与数据说明](PRIVACY.zh-CN.md) 的安全删除顺序分别处理。

## AI 按钮提示未配置或失败

- AI 仅在你手动点击某个 AI 操作时运行，不会自动发送。该点击就是本次直接授权并开始请求，不会再弹出二次确认。
- 至少需要一个已启用的 AI 连接和对应密钥；未临时选择时优先使用已启用的默认连接，默认连接不可用时选择首个已启用连接。只切换连接不会发送请求，手动点击“重新生成”才会使用当前选择的连接。
- 若提示缺少 API 密钥：打开“设置 → AI 连接”，在连接编辑器粘贴新密钥，先点击“测试连接”；测试通过后再点击“保存”。
- 若提示密钥失效：到服务商撤销或更新密钥，回到连接编辑器粘贴新密钥，先点击“测试连接”；测试通过后再点击“保存”。
- 核对接口协议、基础地址和模型名；中转服务不一定完整兼容 OpenAI 或 Anthropic。
- 使用“测试连接”区分密钥失效、余额不足、限流、超时和网络错误。
- 如果留空模型 ID 时默认模型失败：先确认账户和所选地区是否已开通该模型；再填入账户已开通的完整模型 ID 将其固定；然后在当前连接编辑器中点击“测试连接”。
- 编辑器可以用尚未保存的新密钥测试；即使测试成功，仍需点击“保存”才会写入连接元数据和外部密钥文件。
- 未配置密钥不会影响采集。
- 插件不会自动换模型或重试。修正当前连接后，再由你手动发起操作。

AI 结果区只流式显示最终答案，不展示隐藏推理、思维链或深度思考过程。AI 服务启动固定使用 `fetchFullText=false`。AI 内容选择器不会自行发起新的全文或字幕获取；它只检查选择器运行时已有的合格缓存：优先采用已缓存的文章全文或 YouTube 字幕，否则使用 Feed 已有正文、标题和简介。

从列表点击 AI 会先打开内部阅读区。普通网页文章的内部阅读区可能按正常阅读逻辑独立读取缓存或请求发布者页面，因此从列表发起 AI 可能间接产生阅读器网络请求。若希望提高模型使用网页全文的概率，先普通打开并阅读文章，等待网页全文显示且缓存完成，再手动发起 AI；YouTube 先明确点击“获取字幕”，缓存完成后再发起 AI。若阅读器抓取在选择器运行时仍在进行，模型实际收到的内容可能因进入路径和操作时机不同；不能保证该页面请求会被同一次 AI 请求包含，除非缓存已在选择器运行前可用。

## AI 结果找不到

手动 AI 成功后，独立结果写入当前配置的数据根。精确路径格式为：

```text
{dataFolder}/analysis/{itemId}/YYYYMMDDTHHMMSSmmm-{operation}[-N].md
```

结果只有保存成功后才会显示为完成；请求失败（包括缺少或无效密钥）不会创建空白结果文件。重新打开同一条信息与同一种操作时，插件会先复用同一个任务，不会重复请求，并重新连接运行中或已完成的状态；没有内存任务时会读取最新结果并列出历史结果。手动“重新生成”会创建新的独立、不可变结果并保留旧结果，不会覆盖原文件。

关闭文章或折叠结果只会分离界面，不会取消任务。“停止”是明确中止操作，只在任务仍可取消时请求中止；已进入不可逆保存的任务会如实完成。禁用插件或完全退出 Obsidian 会关闭任务运行时，不会让模型任务在后台继续运行。

如果找不到最新结果或历史结果，先核对当前设置中的 `dataFolder`，再确认当前信息和操作类型是否一致，并检查上述精确目录。不要移动、改名或手工编辑分析文件后期待它仍被识别。

如果希望当前结果进入普通笔记：

1. 只有当前任务中可再次验证的精确结果允许插入；历史结果只能打开，不能插入。
2. 来源尚未保存时，插件会先保存来源笔记，再验证当前精确结果并执行插入。
3. 插入内容带 `RSS-DASHBOARD-CN:AI` 标记；已存在同一结果标记时，插件会打开现有位置而不是重复插入。

不要手工破坏 `RSS-DASHBOARD-CN:AI` 标记对；结构异常时插件会拒绝覆盖，以保护笔记。

## 保存 Markdown 失败或出现同名文件

- 检查保存目录是否存在非法字符或只读限制。
- 同一条信息再次保存时，插件会尝试打开已有笔记。
- 不同信息标题相同会使用稳定标识后缀，避免覆盖。
- 网站全文获取失败时，插件可能使用 Feed 中已有内容保存。

## 数据占用空间没有随回退或卸载消失

这是预期的安全边界：

- 从分片存储切回传统 JSON 不会自动删除 `.rss-dashboard-data/feeds/`。
- 从知识库元数据位置切回插件默认位置不会自动删除旧 `data.json`。
- 卸载插件不会删除 `.rss-dashboard-data/`、`信息收集/`、自定义保存目录或外部密钥文件。

先禁用插件并备份，再按 [隐私与数据说明](PRIVACY.zh-CN.md) 的准确路径逐项清理。

## 密钥文件权限或内容异常

默认密钥位置见 [隐私与数据说明](PRIVACY.zh-CN.md)。macOS/Linux 上，插件要求目录和文件仅当前用户可访问；若路径被符号链接替换、JSON 结构损坏或权限无法校正，插件会拒绝继续写入。

Windows 使用当前账户的文件系统保护，不是加密凭证库。若怀疑密钥泄露，应先到服务商撤销旧密钥，再禁用插件并替换本地密钥。

## 报告问题前

可以提供：

- 插件版本、Obsidian 版本和操作系统类型；
- 来源种类；
- 能公开的最小操作步骤；
- 插件生成并由你预览过的安全诊断；
- 不含私人内容的结构化错误码。

不要提供：

- API 密钥或 Authorization Header；
- 完整 `data.json`、`.rss-dashboard-data` 或 `secrets.json`；
- 原始 TikHub/AI 响应、Feed 导出或 OPML；
- 真实 X 账号、关键词、标题、正文；
- 知识库绝对路径、用户目录路径或未清洗截图。
