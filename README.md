# RSS 信息台

RSS Dashboard CN 是一个中文优先、仅桌面端使用的 Obsidian 信息采集插件。它把 RSS、网站、播客、YouTube，以及可选的 X 账号和主题订阅汇集到一个面板中；需要长期保留的内容可以保存为 Markdown，再交给你选择的模型或其他工具继续整理。

当前版本为 `0.1.0`，采用手动自安装方式。它尚不代表已经进入 Obsidian 社区插件目录。

## 它做什么

- 在 Obsidian 内订阅、刷新、筛选和阅读多个信息源。
- 默认在每天打开 Obsidian 时刷新当天尚未成功刷新的来源，也保留全部、失败来源和单一来源的手动刷新。
- 把每日采集结果写入本地索引，把感兴趣的单条内容保存为 Markdown。
- 在阅读区按需获取 YouTube 的公开人工字幕或自动生成字幕，并把结果缓存到本地。
- 为 X 账号跟踪和主题发现提供可选的 TikHub 接入。
- 对选中的单条信息提供手动摘要、翻译为中文、提炼核心观点和深度分析。
- 默认中文界面，也可在设置中切换为英文。

基础采集不需要配置 AI，也不需要 TikHub。只使用 RSS、网站、播客或 YouTube 时，可以一直关闭这两项可选能力。

## 它不做什么

- Obsidian 关闭后不会继续运行，没有常驻守护进程或云端后台任务。
- 不会自动摘要、自动翻译、自动评分、自动排名或自动选择“Top 10”。
- 不会在 AI 服务失败后自动换到另一个模型，也不会自动重试并产生额外费用。
- 不会把 TikHub 的 `Top` 当成内容质量、权威性或推荐分数。
- 不会为 YouTube 下载视频或音频，也不会把字幕之外的内容伪装成字幕。
- 不会在卸载时自动删除已经采集或保存的文件。

## 支持的信息源

| 信息源 | 采集方式 | 备注 |
|---|---|---|
| RSS / Atom / JSON Feed | 订阅源解析 | 沿用上游项目的采集架构 |
| 普通网站 | Feed 自动发现、网页阅读与保存 | 网站结构或访问限制可能影响提取 |
| 播客 | 播客 Feed 和媒体元数据 | 可在 Obsidian 内播放 |
| YouTube | 频道或视频的 Feed/元数据；按需读取公开字幕 | 支持公开人工字幕或自动生成字幕；没有公开字幕时不会用标题或简介代替 |
| X 账号 | TikHub 时间线接口 | 可选，可能产生 TikHub 费用 |
| X 主题 | TikHub 的最新、平台 `Top` 和重点账号观察 | 可选；这些是观察分类，不是插件推荐 |

## 每天打开时刷新

默认刷新模式是“每天打开时刷新”。Obsidian 布局就绪后，插件按本机日期检查每个当前订阅来源：同一天已经成功刷新的来源不再自动刷新，尚未成功的来源才进入本次刷新。启动延迟默认为 5 秒，可在设置中调整。

这个机制只在 Obsidian 正在运行时生效。电脑关机、Obsidian 退出或插件被禁用时不会联网。需要立即更新时，可随时使用手动刷新全部、失败来源或单一来源。

## 安装

手动安装需要把同一版本的三个独立发布文件放进：

```text
{vault-root}/.obsidian/plugins/rss-dashboard-cn/
  main.js
  manifest.json
  styles.css
```

随后重新加载或重启 Obsidian，在“设置 → 第三方插件”中启用 `RSS Dashboard CN`。更新时应同时替换三个文件，不要混用不同版本。

已经完成首次安装后，可以在本仓库中使用非破坏性本地更新命令。目标目录必须显式填写，安装器不会猜测用户目录或知识库位置：

```bash
npm run install:local -- --target "/path/to/vault/.obsidian/plugins/rss-dashboard-cn"
```

该命令会先确认仓库根目录、`package.json` 与 `release/` 中的版本和三个程序文件属于同一次构建，再只替换 `main.js`、`manifest.json`、`styles.css`。安装期间使用插件目录旁的互斥锁，并创建带时间戳的只读备份；备份清单保存为不可被 Obsidian 误加载的 `manifest.json.restore`。它不会修改 `data.json`、知识库根目录的 `.rss-dashboard-data/`、已保存的 Markdown 或知识库外部的密钥文件；安装前后还会以流式哈希校验本地设置与采集历史保持不变。成功后需要重新加载或重启 Obsidian。

完整步骤见 [中文安装指南](docs/INSTALL.zh-CN.md)。

## 第一次使用

1. 打开命令面板，运行“打开 RSS 信息台”。
2. 添加一个 RSS、网站、播客或 YouTube 来源。
3. 保持默认的“每天打开时刷新”，或在设置中选择其他刷新模式。
4. 在列表或阅读器中查看内容；需要长期保留时，点击保存为 Markdown。
5. 只有需要 X 时才配置 TikHub；只有需要手动 AI 操作时才配置 AI 连接和密钥。

未配置密钥时，相关操作会给出配置或错误指引，不影响普通采集。

## 数据存在哪里

默认情况下，数据都保存在本机：

| 类别 | 默认位置（相对知识库根目录） |
|---|---|
| 插件设置元数据 | `.obsidian/plugins/rss-dashboard-cn/data.json` |
| 采集记录、全文/YouTube 字幕缓存、索引、刷新状态、AI 分析产物 | `.rss-dashboard-data/` |
| Feed 分片 | `.rss-dashboard-data/feeds/` |
| 每日 Markdown 索引 | `信息收集/每日采集/` |
| 手动保存的 Markdown | `信息收集/已保存/` |

以上目录可以在设置中改动。若把元数据迁移到知识库目录，`data.json` 会写入配置的目录；改回默认位置时，原副本会保留作恢复用途。

TikHub 与 AI 密钥不写入 `data.json` 或知识库，而是写入桌面系统用户目录中的外部 `secrets.json`。各系统的准确默认路径和权限边界见 [隐私与数据说明](docs/PRIVACY.zh-CN.md)。

默认已启用 CORS 代理并使用“自动轮换”模式。Feed 获取会先尝试直接请求，失败后可能轮换第三方公共代理；全文路径会按当前配置尝试代理回退。代理请求会携带经过编码的完整目标 URL，代理运营方可以还原并看到该地址。你可以在“设置 → 常规 → 代理”中关闭代理或选择/填写代理；关闭 CORS 代理可能降低部分跨域订阅源和全文抓取的成功率。内置代理只提供技术回退，不构成隐私、稳定性或可用性背书。

打开信息台、文章列表、侧边栏或发现页时，即使没有执行刷新，界面也可能自动加载来源提供的远程封面/图片和 Google favicon；只有点击 YouTube 的“内嵌预览”才会访问 `youtube-nocookie.com`。本地保存 Markdown 不等于其中引用的远程图片已经下载到本地，详情见隐私说明。

## YouTube 字幕与播放边界

打开视频文章后，“在浏览器中播放”会交给操作系统的系统默认浏览器；“内嵌预览”才会在 Obsidian 内创建 YouTube 播放器。内嵌预览与系统默认浏览器的登录状态不相通，因此即使浏览器已经登录，内嵌预览仍可能要求登录或受地区、年龄和网络策略限制。

字幕是另一项明确操作。内置路径只尝试 YouTube 当前公开提供的公开人工字幕或自动生成字幕，优先人工原语言轨道；标题和简介不会被表示为字幕，也不会用来填补字幕正文。如果视频没有任何公开字幕轨道，界面会显示“无字幕”，本版本不伪造字幕。内置路径明确确认没有公开字幕后，可选工具或字幕提供方不可用、无轨或临时失败仍会保持“无字幕”状态；如果回退已经取得有效字幕但本地保存失败，则会显示暂时不可用，不会误报“无字幕”。YouTube 的未公开接口形状可能变化，插件不承诺每个公开视频都能持续取得字幕；“无字幕”和“暂时不可用”会分别提示。

插件可以在桌面端使用本机已有的 `yt-dlp` 作为可选本地回退，但普通用户不需要安装它。回退只读取字幕元数据，不读取 Cookie，不使用浏览器登录，不下载视频或音频，也不会写入媒体或字幕输出文件；插件不会自动安装或更新 `yt-dlp`。本版本不包含 Whisper、ASR、FFmpeg、Python、Bun 或字幕 SaaS，不能为没有公开字幕的视频做语音识别。

成功获取的字幕以 `youtube-transcript` 内容类型保存在当前采集数据根目录的 `content/{itemId}.md`。再次打开文章时会直接读取缓存，不产生字幕网络请求；只有明确点击“重新获取字幕”才会重新请求并原子替换现有缓存。插件更新只替换程序文件，会保留该缓存、订阅、设置、API Key 和其他历史数据。

## TikHub 与费用边界

TikHub 只服务于可选的 X 账号和 X 主题来源。插件会在请求前使用单次和每日上限进行预算控制，默认上限分别为 40 次/轮和 100 次/本机日；实际计费、接口可用性和价格由 TikHub 决定，使用前应查看自己的 TikHub 套餐。

主题发现会观察最新结果、平台 `Top` 结果，并可增加重点账号查询。`Top` 只是 TikHub/X 的搜索类别，不表示观点新颖度、公众热度、思考深度、来源权威性或插件推荐。

关闭 TikHub、未配置密钥、密钥失效或达到预算上限时，X 来源会停止或报错；RSS、网站、播客和 YouTube 仍可使用。

## 按需 AI 与隐私边界

AI 仅在你手动选择摘要、翻译为中文、核心观点或深度分析时运行，不会自动生成摘要、翻译或分析。点击某个 AI 操作就是本次直接授权，并立即开始请求，不再弹出二次确认。未临时选择时优先使用已启用的默认连接；默认连接不可用时选择首个已启用连接。只切换连接不会发送请求，手动点击“重新生成”时才使用当前选择的连接发起新请求。

阅读区只流式显示模型返回的最终答案文本，不展示隐藏推理、思维链或深度思考过程，也没有“深度思考模式”界面。这里的“深度分析”是一个手动内容操作，不表示会展示模型内部推理。

AI 服务启动固定使用 `fetchFullText=false`。AI 内容选择器不会自行发起新的全文或字幕获取；它只检查选择器运行时已有的合格缓存：优先采用已缓存的文章全文或 YouTube 字幕，否则使用 Feed 已有正文、标题和简介等当前单条内容。快照不会扫描并发送其他订阅、其他文章、其他笔记或整个知识库。

从列表点击 AI 会先打开内部阅读区。对于普通网页文章，内部阅读区仍会按正常阅读逻辑独立读取缓存或请求发布者页面；因此从列表发起 AI 可能间接产生阅读器网络请求，这与 AI 内容选择器不主动抓全文并不矛盾。希望提高模型拿到网页全文的概率时，请先普通打开并阅读文章，等待网页全文显示且缓存完成，再手动发起 AI；YouTube 则先明确点击“获取字幕”，缓存完成后再发起 AI。若阅读器抓取在选择器运行时仍在进行，模型实际收到的内容可能因进入路径和操作时机不同；不能保证列表触发的页面请求会被同一次 AI 请求包含，除非缓存已经在选择器运行前可用。

同一条信息与同一种操作会复用同一个任务，不会因为重复点击或重开阅读区而重复请求。重新打开时会重新连接运行中或已完成的任务；关闭文章或折叠结果只会分离界面，不会取消任务。“停止”是明确中止操作，会在任务仍可取消时请求中止；已经开始的不可逆保存会如实完成。禁用插件或完全退出 Obsidian 会关闭任务运行时，任务不会在后台继续运行。

结果保存成功后才显示为完成。文件保存在配置的 `{dataFolder}/analysis/{itemId}/YYYYMMDDTHHMMSSmmm-{operation}[-N].md`；重新打开同一操作可以看到最新结果和历史列表。手动“重新生成”会创建新的独立、不可变结果，不会覆盖旧结果。请求失败（包括缺少或无效密钥）不会创建空白结果文件。

只有当前任务中可验证的精确结果允许插入笔记；历史结果只能打开，不能插入。若来源还没有保存，插件会先保存来源笔记，再验证当前结果并写入 `RSS-DASHBOARD-CN:AI` 标记；已存在同一标记时会打开原位置，不会重复写入。

内置连接元数据预设包括 Kimi、DeepSeek、通义千问、GLM、OpenAI、Claude、MiniMax 国内和 MiniMax 海外，以及 OpenAI/Anthropic 兼容中转接口。每个具名官方平台在当前版本中的推荐模型如下：

| 官方平台 | 内置推荐模型 |
|---|---|
| Kimi | `kimi-latest` |
| DeepSeek | `deepseek-v4-pro` |
| 通义千问 | `qwen3.7-plus` |
| GLM | `glm-5.2` |
| OpenAI | `gpt-5.6` |
| Claude | `claude-sonnet-5` |
| MiniMax 国内 | `MiniMax-M3` |
| MiniMax 海外 | `MiniMax-M3` |

- 模型 ID 留空：跟随当前插件版本内置的推荐模型。
- 填写模型 ID：固定使用该模型，后续升级不会覆盖。
- 兼容中转站：必须填写模型 ID。
- 更新插件只替换运行文件，不会删除连接、API Key 或 AI 历史文件。

具名官方预设的接口地址固定；模型 ID 可留空跟随默认，或填写后固定使用。兼容中转站的接口地址和模型 ID 可编辑，服务商以后也可能改变要求。没有密钥、密钥失效、余额不足、限流或网络失败时，插件只显示对应指引，不会自动切换服务商。

模型服务商会接收到你通过手动 AI 操作授权发送的内容，并可能按其政策记录或计费；使用前请自行核对服务商条款。

## 备份与删除

- 备份时至少保留需要的 `信息收集/` Markdown、订阅设置和 `.rss-dashboard-data/`。
- 公开分享任何导出文件前先人工检查；导出内容可能包含订阅地址、X 账号、关键词、标题或文件夹名。
- 公共设置导出不会携带 TikHub/AI 密钥。导入的 TikHub 与 AI 连接会保持禁用或未配置，必须在本机重新绑定密钥。
- 从分片存储切回传统 JSON 时，插件不会自动删除原分片；从知识库元数据位置切回插件默认位置时，也会保留原副本供恢复。
- 卸载前先禁用插件并备份需要的 Markdown。只删除你已核对属于本插件的准确目录，不要直接删除整个知识库或整个用户目录。

详细清理顺序见 [隐私与数据说明](docs/PRIVACY.zh-CN.md)。

## 已知限制

- 仅支持 Obsidian 桌面端；外部密钥存储依赖 Node.js 文件系统能力。
- 网站全文提取受网页结构、登录、反爬策略和网络环境影响。
- YouTube 公开字幕接口可能改变；没有公开字幕的视频不能在本版本中生成字幕，AI 也不能基于未采集的音视频内容分析。
- TikHub 和各 AI 服务商的接口、模型、价格与配额可能变化。
- Windows 的外部密钥文件依赖操作系统账户和文件系统访问控制，不是加密凭证库。
- 自动刷新必须等 Obsidian 打开；若来源当天失败，可手动重试。

遇到问题请先看 [中文故障排查](docs/TROUBLESHOOTING.zh-CN.md)。
